# WhqMusic

WhqMusic 是面向 Windows 的本地音乐播放器，支持音乐库与分组管理、同步歌词、桌面歌词、全局快捷键、元数据编辑、自定义界面和实时音效。

**当前产品版本：1.0**  
**版本基线日期：2026-09-10**

本版功能已由用户确认正常，详见 [工作记录](docs/工作记录.md)。本 README 记录使用方式、构建要求和版本变化；工作记录保留开发过程。

版本标识说明：当前 `CMakeLists.txt` 的工程版本仍为 `0.1.0`，与本次确定的产品版本 1.0 尚未同步。本次文档更新不代表重新生成或核验了发布包。

## 1.0 功能

| 模块 | 功能 |
| --- | --- |
| 本地音乐库 | 导入歌曲与扫描目录；支持 MP3、WAV、FLAC、M4A、AAC、OGG；显示歌曲、歌手和文件大小 |
| 分组与检索 | 自定义分组、行内新建和重命名、管理歌曲所属分组；按歌曲名和歌手筛选当前分组 |
| 文件识别 | 后台扫描元数据，缓存 SHA-256 辅助识别文件改名；保存歌手扫描状态，减少重复扫描 |
| 播放控制 | 播放、暂停、上一首、下一首、音量；顺序、列表循环、单曲循环、随机模式；点击或拖动进度定位 |
| 实时解码 | FFmpeg 实时解码，按播放进度限制缓冲；对部分损坏数据和缺失时间戳进行容错处理；无法继续时停止并记录原因 |
| 音效 | 原声、清澈人声、重低音、现场；共用实时播放链路 |
| 歌词展示 | 读取同名 LRC、内嵌同步歌词及普通歌词；同步高亮、双击定位、长句横向滚动、简繁显示切换 |
| 歌词搜索与写入 | 在线搜索、候选预览、滚动歌词优先与时长差排序；确认后写入歌曲内嵌歌词，支持覆盖确认及播放状态恢复 |
| 元数据编辑 | 查看和编辑常用及扩展文本标签；查看音频参数与 SHA-256；支持文件改名及关联同名 LRC 改名 |
| 界面定制 | 自定义标题栏、内置及自选背景、毛玻璃效果、背景自适应文字颜色；界面与歌词字体字号独立设置和预览 |
| 播放队列与托盘 | 当前播放歌曲高亮、托盘控制；持久化队列及设置，重启恢复队列但不自动播放 |

本版定位为本地音乐播放器，未接入在线歌曲搜索、流媒体曲库或歌曲文件下载。在线歌词搜索属于已有功能，保留使用。格式支持以应用导入范围为准，FFmpeg 支持更多格式并不意味着应用已经开放这些格式；容错也不保证所有损坏文件均可播放。

## 使用说明

1. 解压完整发布目录，运行 `WhqMusic.exe`。
2. 通过底部音乐库入口导入本地歌曲或目录，按需新建分组并管理歌曲。
3. 选择歌曲播放，使用底部控件调整进度、音量、音效和播放模式。
4. 有同步歌词时双击歌词可定位；缺失歌词时可通过歌词区域打开搜索窗口，预览后确认写入。
5. 在歌曲右键菜单中打开元数据编辑；在“设置 → 通用设置”中调整背景、字体和字号，在“快捷键设置”中配置全局快捷键。
6. 点击主界面歌词区域、任务栏预览或托盘中的“桌”按钮，显示或隐藏桌面歌词。
7. 通过托盘菜单退出程序；再次启动时恢复已保存队列和设置。

### 全局快捷键

快捷键注册成功后，在其他应用位于前台时也可控制播放器。

| 操作 | 默认快捷键 |
| --- | --- |
| 播放 / 暂停 | `Ctrl+Alt+F5` |
| 上一曲 | `Ctrl+Alt+←` |
| 下一曲 | `Ctrl+Alt+→` |
| 音量增加 | `Ctrl+Alt+↑` |
| 音量减少 | `Ctrl+Alt+↓` |
| 静音 / 取消静音 | `Ctrl+Alt+M` |
| 切换播放模式 | `Ctrl+Alt+R` |

在“设置 → 快捷键设置”中操作：

1. 双击快捷键输入框，按下需要的组合键，松开主键后完成录入；每项设置一个组合键，不支持连续多组按键。
2. 录入时按 `Backspace` 清空该项，按 `Esc` 或点击其他位置结束录入。
3. 使用每项的“启用”复选框控制是否注册，或通过“全部启用”“全部禁用”“恢复默认”批量管理。
4. 修改后自动保存并立即尝试注册。“已生效”表示可用；“被占用”或“注册失败”时，可将鼠标移到“重试”按钮查看原因，更换组合键或解除占用后重试。

音量快捷键每次调整 5 个百分点；取消静音时恢复静音前的音量。播放器正在编辑歌曲文件或处于不允许操作的界面状态时，快捷键不会执行播放控制。

### 桌面歌词

以下三个入口均使用“桌”字按钮，显示状态相互同步：

- **主界面**：歌词区域顶部的“桌”按钮。
- **任务栏预览**：鼠标悬停播放器任务栏图标后，预览操作栏最右侧的“桌”按钮。
- **系统托盘**：右键播放器托盘图标，点击播放模式右侧的“桌”按钮；开启时显示选中底色。

桌面歌词为独立置顶窗口，主界面最小化后仍可显示。窗口中的操作方式如下：

- **交替播放**：第一句在上行播放，第二句在下行预告；播放第二句时仍保持在下行，上行替换为第三句，后续依次交替。拖动播放进度后，按歌词序号恢复对应行或列。
- **横竖排版**：拖动边缘改变窗口长宽比例，自动切换横排或竖排。横排上行左对齐，下行右缩进两个汉字宽度；竖排从右列开始交替播放，右列起点比左列高两个汉字高度。偏移随当前字体尺寸调整。
- **同步与滚动**：有字词时间的歌词按实际时间逐字填色；普通同步歌词按句内进度填色。长句在各自显示区域内滚动，无同步歌词时显示歌曲标题及歌词状态。
- **字体与配色**：字体沿用通用设置中的歌词字体，字号随窗口尺寸适配。点击工具栏中“A＋彩色下划线”按钮选择配色，也可恢复默认配色。
- **工具栏**：鼠标移入窗口后显示上一曲、播放 / 暂停、下一曲、播放模式和配色按钮。关闭按钮“×”固定在右上角；宽度不足时，其余按钮从下一行开始分行排列。
- **移动与缩放**：拖动窗口空白区域移动，拖动边缘或角落缩放。横排最小尺寸为 240×130，竖排为 130×240；允许部分移出屏幕或跨显示器放置，但至少保留 48×48 的可拖动区域。
- **保存与关闭**：位置、尺寸、方向和配色会自动保存。点击“×”仅隐藏桌面歌词，也可再次点击任一入口的“桌”按钮将其隐藏。

### 文件与数据

- 音乐库通常记录原歌曲路径，导入不会复制一份歌曲；移动或删除原文件会影响播放。
- 元数据保存及内嵌歌词写入会修改原音频文件，文件改名操作也会影响关联同名 LRC。
- 歌词读取优先级为外部同步 LRC、内嵌同步歌词、内嵌普通歌词。已有外部 LRC 可能优先于新写入的内嵌歌词显示。
- 歌词下载写入歌曲内部，不另存新的 LRC；已有 LRC 仍可读取。
- 数据库使用 Qt 的 `QStandardPaths::AppDataLocation` 下的 `music.db`，保存音乐库、分组和设置等数据，不应假定数据库位于程序目录。
- 本地播放不需要音乐平台账号；在线歌词搜索需要网络，结果及可用性取决于对应服务。

## 技术栈

| 技术 | 当前使用方式 |
| --- | --- |
| C++17 | 主要开发语言 |
| Qt 6 Widgets / QSS | 桌面界面、自绘控件与样式 |
| Qt Multimedia | `QAudioSink` 音频输出及元数据扫描相关能力 |
| Qt Concurrent / 工作线程 | 后台扫描、文件处理及实时解码 |
| Qt Network | 在线歌词请求 |
| Qt Sql / SQLite | 本地音乐库、分组、队列和设置持久化 |
| FFmpeg | 实时解复用、解码及重采样；仓库附带 7.1.5 公共头文件，运行时动态加载兼容 DLL |
| TagLib 2.1.1 | 音频标签与内嵌歌词读取、写入，通过 CMake FetchContent 获取 |
| CMake / MinGW-w64 | 构建配置与 Windows 编译 |
| PowerShell / windeployqt | Release 构建及运行依赖部署 |
| SVG / Qt Resource | 图标、背景和样式资源内置 |

实际播放路径为 `AudioDecoderWorker → PCM → AudioEffectProcessor → QAudioSink`，由 `AudioPlayer` 与播放控制器协调进度和状态；实际播放不再由 `QMediaPlayer` 解码，元数据扫描仍可使用它。歌词实现使用 LRCLIB 和酷狗歌词接口。

## 编译要求

当前维护环境为 **Windows 64 位 + Qt MinGW 64 位工具链**。其他系统和编译器组合未在本 README 中承诺支持。

| 依赖 | 要求或项目参考配置 |
| --- | --- |
| Qt | 参考版本 **6.11.2 mingw_64**；必须包含 Concurrent、Multimedia、Network、Sql、Widgets 模块 |
| C++ 编译器 | 支持 C++17，并与 Qt Kit 匹配；参考 **MinGW 13.1 64 位** |
| CMake | **3.21 或更高** |
| 构建工具 | 打包脚本使用 `mingw32-make`；Qt Creator 的 Kit 可使用已配置的 Ninja |
| Git / 网络 | 首次配置通过 Git 从 GitHub 拉取 TagLib `v2.1.1`，需要 Git 和对应网络访问能力 |
| FFmpeg 运行库 | 与程序同为 64 位且 ABI 兼容的 `avutil-59.dll`、`swresample-5.dll`、`avcodec-61.dll`、`avformat-61.dll` |
| PowerShell | 执行 Windows 打包脚本 |

CMake 只检查 Qt 6 模块，没有声明最低 Qt 6 小版本；不能据此推断所有 Qt 6 版本都能编译，建议采用上述参考 Kit。

FFmpeg 头文件已在 `third_party/ffmpeg/include`，不需要另行编译 FFmpeg 或安装 `ffmpeg.exe`。Windows 配置默认从所选 Qt Kit 的 `bin` 目录寻找上述 DLL，缺失时会直接报错。可通过 CMake 缓存变量指定其他兼容目录：

```text
-DWHQ_FFMPEG_RUNTIME_DIR=D:/path/to/compatible-ffmpeg/bin
```

## 编译与运行

### 使用 Qt Creator

1. 安装上述 Qt、MinGW、CMake 和 Git，确认所需 Qt 模块齐全。
2. 用 Qt Creator 打开根目录的 `CMakeLists.txt`。
3. 选择 Qt 6.11.2 MinGW 64 位 Kit，并选择 Debug 或 Release 配置。
4. 首次运行 CMake 时等待 TagLib 获取完成；如提示缺少 FFmpeg DLL，在项目 CMake 配置中设置 `WHQ_FFMPEG_RUNTIME_DIR` 后重新配置。
5. 构建 `WhqMusic` 目标并运行。CMake 会将指定 FFmpeg DLL 及相关说明复制到可执行文件目录。

修改依赖、CMake 配置或切换 Kit 后应重新配置。不同编译器或生成器使用不同构建目录，避免混用缓存。

### 命令行构建及部署

在项目根目录打开 PowerShell。安装路径与项目脚本默认值相同时执行：

```powershell
.\scripts\package-windows.ps1
```

自定义工具路径时执行：

```powershell
.\scripts\package-windows.ps1 `
    -QtRoot 'D:\qt\6.11.2\mingw_64' `
    -MinGwRoot 'D:\qt\Tools\mingw1310_64' `
    -CMakeRoot 'D:\qt\Tools\CMake_64' `
    -BuildDirectory 'build\windows-release' `
    -OutputDirectory 'dist\WhqMusic'
```

以上路径是参考安装位置，需要替换成实际路径。脚本同时完成配置、编译和部署，不是只编译命令。它没有直接暴露 FFmpeg 目录参数；如需自定义，可先通过 Qt Creator/CMake 在同一构建目录设置该缓存变量，再运行脚本。

## Windows 打包

脚本依次执行 Release 配置、并行编译、`windeployqt` 部署，然后显式复制四个 FFmpeg DLL 和 `licenses` 目录。

| 内容 | 默认位置 |
| --- | --- |
| Release 构建目录 | `build/windows-release` |
| 发布目录 | `dist/WhqMusic` |
| 程序入口 | `dist/WhqMusic/WhqMusic.exe` |

**脚本会清空指定发布目录后重新部署，请勿将其指向个人资料或音乐目录。** 构建与输出目录参数按项目相对路径使用。

发布时复制整个 `WhqMusic` 文件夹，包含 Qt 插件、运行库、FFmpeg DLL 和许可证说明，不能只发送 EXE。源码或 README 更新不会自动更新已有发布包。

常见配置问题：

- 找不到 Qt：确认 Kit 和安装路径，脚本需要 `qt-cmake.bat` 与 `windeployqt.exe`。
- TagLib 获取失败：检查 Git 和 GitHub 连接；已有完整本地源码时，可使用 CMake 的 `FETCHCONTENT_SOURCE_DIR_TAGLIB` 指定源码目录。
- FFmpeg DLL 缺失或 ABI 不匹配：使用符合上述名称、架构和版本要求的运行库；不要通过改 DLL 文件名替代版本匹配。
- 发布后无法加载 SQLite 或平台插件：确认完整部署并保留 `windeployqt` 生成的插件目录。

第三方组件说明见 [FFmpeg 说明](third_party/ffmpeg/README.md)及各组件自身许可证；发布时应保留相关声明。

## 版本维护规则

1. 本文的“1.0 功能”是基线，后续新增功能追加到下方版本记录，不覆盖历史版本的功能范围。
2. 新功能开发期间写入“未发布”区域，标明实际状态；只有构想的内容不得写成已实现。
3. 发布时将“未发布”内容整理为独立版本节，最新版本排在前面，更新文档顶部的当前版本和日期。
4. 每次新增功能同步补充用途和操作入口；影响依赖、编译、部署、存储或兼容性时，同步更新本文对应章节。
5. 版本记录使用统一字段：新增、改进、修复、构建与依赖、兼容与数据、验证与发布。无变化可写“无”。
6. 发布前同步确认 CMake 工程版本等版本标识；区分用户确认、实际构建验证和发布产物生成，不用文档版本代替产物版本。
